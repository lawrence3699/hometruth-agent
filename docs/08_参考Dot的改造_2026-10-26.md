# 参考 Dot 的架构，给语音助手加一层"持久状态"（2026-10-26）

超亮 10-26 发来 Dot 的实现资料（LLM + 持久任务状态 + 调度器 + 工具执行 + 权限门；任务状态机、三层记忆、多执行通道、协调者 + 并行工人、动作审查门、幂等恢复），问能不能照它优化我们的语音助手；同时要求多用赞助商技术、多点有趣的东西。

## 人话版

Dot 的核心不是"更会聊"，而是**用户不在的时候任务照样往前走、回来接得上、同一件事不做两遍**。我们的租房核对员本来是"一问一答、关掉页面就什么都忘"（10-26 上午刚加了记忆，只记需求）。这次加的是三件：

1. **信念日志**（`src/voice/beliefs.py`）：每套房每一格的结论有版本号。开查时来源说的是 v1，中介回复后翻成 v2，再翻就是 v3；只追加、从不改旧行，每行写清谁让它变的、哪个会话、什么时候、翻转前后的排名。租客下次回来，这些翻转照样算数（不用再粘一遍回复）。
2. **收件箱**（`src/voice/inbox.py` + `POST /api/inbox`）：中介的回复可以在租客不在的时候到（邮件 / 短信的 webhook，演示里用 `scripts/agent_reply.py` 代替）。租客回来，开场就说 "While you were away, the agent for 2 Harrow Crescent replied."，点 Same again 时先把这条折进来再排名；导览中途到的，下一句话前就 "Just in, by text: …" 当场翻格、卡片跟着变。
3. **Nemotron 读回复**（`src/voice/replies.py`）：以前只认三句固定句式（pets are fine / no pets / living room only）。现在任意一句中介的话，Nemotron（经 Meterless Nightshift 转发）读成 {哪一格, 新状态, 引用原话哪一段, 一句解释}，规则校验（格子在清单上、状态四选一、引用必须是原话子串、解释不许冒出新数字），不过就退回那三条规则。

还顺手：**开场提还在等的问题**（"You were still waiting on the agent about pets at 2 Harrow Crescent."，每套房最值得问的那个问题记进记忆 `open`）；**同一条回复第二次来不重做**（"I already have that reply noted."）。

## Dot 的概念 ↔ 我们做了什么

| Dot 里的东西 | 我们怎么对应 | 文件 |
|---|---|---|
| 持久任务状态（任务不随会话消失） | 信念日志：每格版本化、只追加；租客回来 `attach_renter` 重放恢复 overrides | beliefs.py；policy.Session.attach_renter / _apply_reply |
| 三层记忆：当前上下文 / 持久笔记 / 任务状态 | 当前上下文 = Session（profile、plan、pos）；持久笔记 = memory.py（需求、前几套、open loops；H-MEM 风格）；任务状态 = beliefs.py（World Model 风格） | memory.py、beliefs.py |
| 等待 / 唤醒（任务等外部事件再推进） | 收件箱：中介回复到了先排队，租客下一句话或下次开查时折进来（没有后台调度器——语音助手不能自己开口，所以是"下一个触发点处理"） | inbox.py；policy.Session._inbox_now |
| 多执行通道（同一个任务从不同入口推进） | 回复从三处进来：租客口述 / 粘贴（agent_reply）、离开时的 webhook（inbox）、导览中途的 webhook（inbox_live）；三条路同一个 `_apply_reply` | policy.py |
| 幂等恢复、去重编号、重试前先核对 | event_id = sha1(房源 + 格 + 新状态 + 原话)；会话内 changes 和日志里都查过才落；收件箱先标已读再处理 | beliefs.event_id / seen；inbox.mark_read |
| 动作审查门（外部动作先过人） | 我们没有外部动作（不发邮件、不替租客答应）；信念翻转会说出来，Changes 面板列出 v1 → v2 和谁读的，租客随时能看 | ui-qi.js change() |
| 协调者 + 并行工人 | 没做（我们的"工人"是五个来源查询，已经并行；语音场景再加一层编排只会慢） | — |
| 标签页互斥、浏览器自动化 | 不适用 | — |

## 赞助商技术用在哪

- **Meterless**：Nightshift 转发所有模型调用（读回复的请求 task=agent_reply 也记在 runs/llm_log.jsonl）；信念日志按 World Model 的口径自实现（版本化、只追加），记忆按 H-MEM 的口径自实现——README 和欢迎框的小字如实写"自实现"，没用官方包。
- **NVIDIA Nemotron**：读任意中介回复（replies.py），Changes 面板标 "read by Nemotron"；需求解析、台词、看图本来就是它。
- **Zetaris**：没变（来源查询那层）；信念日志里 evidence 行的 table / row 沿用矩阵的编号，接真数据时 request_id 直接填进来。

## 怎么演示（两分钟）

1. 第一次：说需求 → 导览到 Harrow → 粘一句 "The agent said pets are fine…" → 翻格、重排、Changes 面板 v1 → v2。
2. 关页面。终端：`python3 scripts/agent_reply.py --renter <浏览器 localStorage 的 ht_renter> --listing L-0001 --text "Hi, the split system is in the living room only, not in the bedroom." --channel email`
3. 再打开：欢迎框多两行（While you were away: 1 agent reply · 12 Alder Lane；On file: 1 belief flip）；点 Same again → "By email, the agent for 12 Alder Lane says air conditioning goes from unknown to conflict; I've folded that in before ranking." → 卡片已经是新状态。
4. 导览中再跑一次脚本（换一句话、换一套房），然后随便问一句 → "Just in, by email: …" 当场翻。

## 验证

- tests/test_beliefs_inbox.py 12 个用例（版本 / 去重 / 重放 / 收件箱 / 校验 / 四条会话流程 / hello 视图 / Forget me）；全套 107 个。
- 截图脚本新步骤：qi_8630_13_welcome_back（框里多了 away / open / on file 三行）、14_away_folded；qi_8631_06/07 同、08_away_folded。
- 没验的：真麦克风下导览中途 "Just in" 的听感；Nemotron 读非英语或很长的回复。

## 没照搬的，和为什么

- 后台调度器 / 定时唤醒：语音助手不该自己出声；收件箱在下一个触发点处理已经够演示，也不会吓到人。
- 并行工人：五个来源已经并行，再编排是为了架构图好看，不是为了用户。
- 权限门：我们不替租客做任何外部动作，所以没有要审的动作；要审的是"信念为什么翻了"，面板已经给了版本和来源。
