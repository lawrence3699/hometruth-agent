# Domain 详情页的 3D Flyover / 3D Tour 是怎么做的，我们用赞助商技术能做到哪一步（2026-10-27）

看的页面：https://www.domain.com.au/3-mackillop-place-mount-eliza-vic-3930-2021062328?topspot=1 （The Block House 2，`topspot=1` 只是广告位参数，和功能无关）。截图在 docs/reference/detail_refs/。

## 1. 那个页面上有什么

媒体一栏五个 tab：**42 Photos / Floorplan / 3D Tour / 3D Flyover / Video**。

- **3D Flyover**：一个会自己绕着房子转的三维外景模型，带放大缩小和暂停（截图 domain_04）。
- **3D Tour**：Matterport 室内漫游（页面下方 "Matterport 3D Tour" 一节是同一份数据的嵌入）。

## 2. 它是怎么实现的（在页面里看到的证据）

| 证据 | 说明 |
|---|---|
| 点 3D Flyover 后页面里出现 iframe `https://www.domain.com.au/virtual-viewer/exterior?listingId=2021062328` | 查看器是 Domain 自己的前端应用（Next.js，静态资源在 `s.domainstatic.com.au/fe-server-virtual-viewer/…`），不是第三方嵌入 |
| 查看器页面只有一个 1920×1002 的 `canvas`，WebGL 可用，没有 `video` | 是实时三维渲染，不是预渲染视频 |
| 查看器加载 `https://www.domain.com.au/matterport-community/<uuid>/meta.json` | 三维数据来自 **Matterport 扫描**（Domain 把 Matterport 的模型搬到自己域名下） |
| 页面数据 `__NEXT_DATA__` 里：`"tourProvider":"Domain","hasMatterportExterior":true,"hasMatterportInterior":true` | 这套房做了 Matterport **外景 + 内景**两次扫描 |

一句话：**有人拿 Matterport 相机（或支持 LiDAR 的 iPhone）到现场把房子内外扫了一遍，Matterport 云端算出带贴图的三维网格，Domain 用自己写的 WebGL 查看器播放，外景自动环绕就是 "3D Flyover"，内景漫游就是 "3D Tour"。** 没有现场扫描，这两个功能都不存在；页面上大多数房源也没有它们。

## 3. 只有挂牌照片 + 户型图，能做出一样的东西吗

做不出"一样"的，原因三条，都是我们试过或查过的：

1. **真正的三维重建要几十到几百张互相重叠的照片**（摄影测量、NeRF、高斯泼溅都一样）。挂牌照片一套 5 到 10 张，每张拍不同房间，几乎没有重叠，算不出几何。
2. **生成式"照片转三维"会改掉已经拍到的东西**。10-24 我们在 103 Quay 上试过 World Labs Marble：能漫游，但墙色、家具、布局被改了，侧面拉伸有缺口（docs/reference/103_quay_3d_experiment.md）。租客看到的和实际不符，和"核对员"的定位相反。
3. **赞助商工具包里没有三维重建模型**：NVIDIA 给的是 Nemotron（文字 + 看图），Meterless 的照片转三维当时需要 DGX Spark 环境，Zetaris 是数据层。

所以：细节"可能有出入"没问题，但不能用生成模型把房间编出来。

## 4. 我们能做的：从户型图"立起来"的玩偶屋（Dollhouse）

思路：**几何来自户型图，内容来自照片，语义来自 Nemotron VL，光来自我们已有的日照几何。** 每一步都是赞助商技术或我们已有的东西，没有一处是凭空生成。

| 步骤 | 怎么做 | 用到谁 |
|---|---|---|
| 1 房间分割 | 户型图黑线是墙、白区是房间：阈值 + 连通域，得到每个房间的多边形 / 外接框（纯 PIL + numpy） | 我们自己 |
| 2 房间命名 | 在每个区域中心盖一个编号章（和照片盖章同一套做法），问 Nemotron VL "编号 3 是什么房间"，返回 living / bedroom 1 / kitchen / bathroom / balcony / hall / outside | **NVIDIA Nemotron VL**（经 Meterless Nightshift 记录，没视觉 lane 就直连并如实记） |
| 3 照片归房间 | 每张挂牌照片问 Nemotron VL 是哪类房间、看到什么（已有 photo_facts 的 room 字段可复用），对到步骤 2 的房间上 | **NVIDIA Nemotron VL** |
| 4 立起来 | 浏览器里 three.js：户型图贴在地板上，房间轮廓挤出半透明墙，照片做成立在对应房间里的"相片板"，相机像 Domain 一样自动环绕，可暂停、缩放；点房间飞过去看这间的照片 | 我们自己（three.js，MIT） |
| 5 太阳 | 冬至 / 夏至 + 小时滑杆，用 src/sun/solar.py 已算好的太阳轨迹和指北针方向打一盏平行光，看阳光从哪面进来 | 我们已有（E2 日照几何） |
| 6 证据 | 房间表、照片归属都写进 floorplan_facts / photo_facts 同一类日志，详情页里每个房间标签能点开看"谁读的、置信度" | **Zetaris**（真数据接上后这些表走联合查询）+ **Meterless**（调用记录） |

诚实标注：界面上写 **"Approximate: built from the floor plan, not a scan. Room sizes indicative."**

适用范围：9 套真房源里 3 套有户型图（6/104 Botany St、56 Oberon St、438-448 Anzac Pde），合成房源没有户型图，所以这个 tab 只在有户型图的房源出现。

## 5. 评委可能问

- **这是三维重建吗？** 不是。是户型图挤出来的近似模型，照片贴在对应房间。我们试过生成式重建，它会改掉拍到的东西，所以不用。
- **Nemotron 在里面干什么？** 认房间（户型图上编号区域是什么房间）、认照片（这张是哪间）。几何不让模型猜，模型只做"看图说话"。
- **和 Domain 的区别？** Domain 要现场扫描，我们只要挂牌页就能看个大概，并且把日照、核对状态直接画在房子上。
