# 维度清单（v1）

整理日期：2026-10-24。配合《租房 Agent：黑客松方案》和附录《判断规则与证据分级》使用。

这是 Agent 要核对的"条件"全集。每条给出：用户会怎么说、属于哪一层（房源 / 房间 / 时间 / 位置）、筛选阶段能用什么材料、签约时会多出什么材料、证据档位（读 / 推 / 算 / 问）、对应的判断规则编号（附录第 3 节）。"首版"列打 √ 的是周六周日必须做的，其余有余力再加。硬条件还是软偏好由用户说了算，表里不预设。

把用户的大白话对到这些编号上，是首版第一件事（需求变清单）的工作；每个编号在数据 schema 里都有对应字段。

材料分五段（代码字段 stage，定义见 docs/00 第 6.1 节）：listing 挂牌就有的（文案、features、价格、照片、户型图）、public 公开可查可算的（中位租金、通勤、太阳几何、噪音）、agent 问中介能拿到的（中介回复、by-laws、法定披露）、viewing 自己看房看到的（租客按清单拍的照片和勾选，替代原来的"看房报告"；代看房只是可选服务）、signing 签约时才拿到的（租约草案、条件报告、inventory）。下表的"筛选阶段材料"指前四段里能用的，"签约时新增"指 signing 段，只做最后核对、不参与排名。

每一格说三件事：直接证据是什么（有支持）、间接证据只能说明什么（推断）、还未知的下一步三选一（代码字段 next.kind）：`ask_agent` 问中介、`see_at_viewing` 看房时自己看、`check_at_signing` 签约时核。首版维度逐条的直接 / 间接 / 下一步表在 docs/00 第 6.4 节。

开查前必填（反问规则，docs/00 第 4.3 节）：A1 周租预算、B1 几房、G1 区域或通勤锚点、A4 入住日期、J1 宠物。这五项为空时程序让助手反问，一次最多两项、最多两轮；其他项为空一律先假设并说出口，不问。

## 两条使用说明

- 用户的一句话可能同时命中多条（"常做饭"命中 C3、C5、C7 的排风和 B8 的通风）；拆分规则由需求解析 prompt 决定，这里只定编号。
- 状态上限随材料段变化：只有 listing 和 public 两段时，很多条最多到"推断"或"未知"；agent 段的中介回复和 viewing 段自己看到的才把它们升为"有支持"；signing 段的条件报告、合同、inventory 只做签约前最后核对，不参与排名。比较房源时要按同一批材料比：A 房有中介回复、B 房没有，B 房的未知不是扣分，是"待确认"，下一步照样标出来。
