# 判断规则与证据分级（方案附录）

整理日期：2026-10-24（悉尼）。配合《租房 Agent：黑客松方案》第 3 节使用。
所有法律和表格事实均于 2026-10-24 从 NSW 官方页面和 Residential Tenancies Regulation 2019 Schedule 2 表格原件核对，链接在文末。

## 1. 规则是怎么定出来的

方案初稿里的判断规则来自三处：10-23 会议上的例子（照片里的沙发可能是上个租客的）、一份真实的代看房记录样本（Doncaster Ave，docs/reference）、以及 Codex 从 103 Quay 案例总结的几条。初稿没有拿 NSW 的正式材料逐条核过，这一版补上。

定规则的方法是对每份材料问三个问题：
1. 这份材料在法律或业务上到底断言了什么？
2. 它没断言什么？
3. 要确认，得看哪份材料，或者问谁？

规则编号带前缀 R（例如 R-A1），以区别于《维度清单》里的维度编号。每条规则都写成同一种句式："材料 X 只断言 Z，所以不能推出 Y；确认途径是 W。"写不成这种句式的，就不进规则表。

证据分四档：
- 读：材料里白纸黑字，直接读。
- 推：要跨材料推断，带置信度。
- 算：地址加公开数据算出来。
- 问：现有材料答不了，进"问中介清单"。

结论状态四种：有支持、推断、冲突、未知。"有支持"再标来源分量：法定表格、合同条款、中介声明、挂牌营销，分量依次递减。

每格三件事（2026-10-27 起，和代码一致）：矩阵里每一格，不管什么状态，都要能说出三件事——
1. 直接证据是什么：有，就是"有支持"。
2. 间接证据只能说明什么：只到"推断"，并写明它推不出什么（"有空调"推不出"卧室有空调"）。
3. 还未知的下一步三选一（代码字段 next.kind）：问中介 `ask_agent`、看房时自己看 `see_at_viewing`、签约时核 `check_at_signing`。

材料按拿到的时点分五段（代码字段 stage，定义见 docs/00 第 6.1 节）：listing 挂牌就有的、public 公开可查可算的、agent 问中介能拿到的、viewing 自己看房看到的、signing 签约时才拿到的。signing 段只做最后核对，永远不是排名的证据来源。租客申请前拿不到第三方看房报告，所以它不是材料；代看房只是可选服务，记录进 viewing 段。

## 2. 材料清单：谁手上有、什么时候拿到、分量多重

| 材料 | 段 | 谁有 | 租客什么时候拿到 | 分量 | 能直接读出什么 |
|---|---|---|---|---|---|
| 挂牌页（REA / Domain） | listing | 中介 | 一开始 | 营销，受消费者法约束不得误导 | 周租、bond、入住日、几房几卫几车位、features 勾选、文案、照片、看房时间 |
| 照片 | listing | 中介 | 一开始 | 房产内照片不需标注；禁止数字增删特征 | 炉灶形态、空调内机、窗帘、地面材质、阳台视野 |
| 户型图 | listing | 多数有 | 一开始 | 非法定，常标 indicative / not to scale | 房间关系、标注尺寸、指北针（有才有） |
| Strata by-laws | agent | 法定 | 签约前必须给，一问通常就给 | 法定 | 宠物、噪音、地板、短租、阳台 |
| Building handbook / residents' guide | agent | 新楼大楼有 | 看中介 | 非法定 | 管理员工时、包裹房、垃圾道、电梯刷卡、搬家预约 |
| 标准租约草案 | signing | 中介 | 申请通过后、签约前 | 合同 | 租金、bond、预付、租期、水费谁付、包含项、附加条款 |
| 条件报告（Schedule 2） | signing | 房东 / 中介填 | 签约前或签约时 | 法定表格 | 逐房 clean / undamaged / working 的 Y/N 加评语；最低标准 7 项；霉菌潮湿、虫害 Y/N；烟雾报警器；电气安全开关；电话线、网络线是否接通；水效 |
| Inventory | signing | furnished 才有 | 签约前 | 合同附件 | 家具电器清单 |
| 必须披露的事实 | agent | 房东 / 中介 | 一问就必须如实答 | 法定义务 | 见规则 R-E2 |
| 中介回复（邮件 / 短信） | agent | 中介 | 一问就有，带时间戳 | 中介声明（低于法定表格和合同） | 房间级空调、家具是否随租及哪些、房东对宠物的态度、维修安排、法定披露的答复 |
| 看房照片与勾选（租客自己按清单拍、勾） | viewing | 租客 | 看房当天 | 自己看到的，直接证据 | 炉灶、空调内机位置、新旧、霉味、水压、白天噪音、看房时段的日照、没拍到的房间仍是未知 |
| 物业维护记录（空调保养、除虫） | agent | 中介系统 | 要问 | 业务记录 | 保养和除虫日期 |
| Strata AGM 纪要、维修记录 | agent | 房东 | 租客无权直接查，只能问 | 业务记录 | 漏水、电梯、噪音投诉、levies |
| 中介 CRM 统计 | agent | 中介 | 租客问不到正式数据，口头问 | 业务记录 | 询盘数、到场数、申请数、在市天数 |
| 公开数据（地址算） | public | 公开 | 随时 | 官方统计 | 租金中位数、交通时间、建筑高度、机场噪音等高线、洪水图、酒牌场所、区域犯罪统计 |

三个要点：
- 看房报告不是材料。租客申请前拿不到第三方看房报告，中介不出、网上也查不到；替代它的是租客自己看房时按清单拍的照片和勾选（viewing 段）。代看房只是可选服务，记录同样进 viewing 段，作者标 proxy。
- 条件报告不是筛选阶段的材料。NSW 规定它在签约前或签约时给租客，租客 7 天内回签。所以它是"签约前的最后核对"，不是筛选房源的输入。
- 中介 CRM 数据只有产品卖给中介时才读得到；租客侧只能口头问，答复记为"中介声明"。

## 3. 规则表

### A. 挂牌页与 features 勾选

- R-A1 features 是房产级勾选。"Air conditioning" 不说哪个房间、几台、冷暖。条件报告里也只有 GENERAL 一行 heating/air conditioning 的 Y/N。所以"有空调"推不出"卧室有空调"；确认靠照片里的内机位置（推断）或问中介。
- R-A2 文案是营销，不是事实陈述。NSW 广告指引点名 "minutes to"、"close to"、"stroll to" 这类模糊说法容易误导，要求用具体距离。"sun-drenched" 同理只能当线索（推断，低置信），要靠指北针、楼层、遮挡核。
- R-A3 "Furnished" 勾选不说明有哪些家具。家具以 inventory 或合同包含项为准；照片里的家具不算。
- R-A4 挂牌租金只是报价。合同签了才是租金；和 DCJ 租金中位数比较时要注明：中位数是该季度新 bond 的中位数，不是挂牌价，样本 10 个以下不公布。

### B. 照片

- R-B1 NSW 指引只禁止数字增删特征、只允许补光，没有专门规定 virtual staging 必须标注。所以：有 Virtual Staging 水印的家具视为不存在；没有水印也不证明家具随租，可能是上个租客或业主的。从 2026-09-21 起拍到现租客物品需租客书面同意，说明挂牌照片经常包含现租客的东西。
- R-B2 炉灶：可见明火炉架是燃气；平面玻璃是电，但陶瓷炉和电磁炉从照片分不出来，所以"电磁炉"保持未知，确认看型号或问。
- R-B3 挂牌照片在最有利的时段拍。照片推不出日照时长，只能推窗户大致朝向和有无遮挡物（推断）。
- R-B4 没拍到的房间是未知，不是"没问题"。

### C. 户型图

- R-C1 有指北针才能定朝向；没有就是未知，最多用建筑轮廓加阳台位置给低置信推断。
- R-C2 尺寸是标注尺寸，图常标 not to scale。家具放不放得下只能用标注尺寸粗算，墙厚和门洞位置不可靠。
- R-C3 单元在楼内的位置、楼层、邻楼高度决定遮挡，户型图不含这些。所以日照结论最多到"推断"，除非拿到楼层平面和楼层标高。

### D. 条件报告

- R-D1 签约前或签约时才拿到。筛选阶段它是"将来可得"的证据（下一步标 check_at_signing）；流程上当作签约前最后核对硬条件的一步，永远不是排名的证据来源。
- R-D2 它断言的是起租时刻、由房东或中介填写、租客可以不同意的 Y/N。working=Y 不说明性能（空调制冷够不够），也不记"几台"。
- R-D3 霉菌潮湿、虫害在表上有专门的 Y/N。有表且填 No，记为"有支持（房东声明，起租时点）"；其他材料没提到霉菌，不等于没有。
- R-D4 表上列了才会被记录。插座只在 lights/power points 一栏合并记，不记数量；窗帘只记 blinds/curtains 是否完好，不记类型；隔音、采光时长、噪音根本不在表上。
- R-D5 通信栏只记电话线、网络线是否接通，不记 NBN 类型和速度。NBN 类型按地址公开查（算），速度问不到。
- R-D6 最低标准 7 项是法定底线：adequate lighting、ventilation、outlets 不等于采光好、通风好、插座够用，adequate 只是法律最低。

### E. 合同与法定披露

- R-E1 租金、bond（不超过 4 周租金）、预付（不超过 2 周）、租期、水费、包含项、附加条款：读合同。
- R-E2 必须如实告知的事实，直接问，答复记为"中介声明"，没问过的是未知，不是"没有"。清单：5 年内水灾或山火；看不出来的重大健康安全风险；5 年内发生过严重暴力犯罪；在松散填充石棉登记册上；2 年内用于制毒或种毒；外墙可燃包层整改令或申请；固定租期内已排定的公共部分大修；拿不到停车许可的区域；垃圾服务与周边不同；别人可合法使用的车道。签约前另外必须告知：已备好出售合同、抵押权人追索、strata 更新委员会已成立；strata 物业必须给 by-laws 副本。说假话或隐瞒，租客可以解约或去 NCAT。
- R-E3 宠物：2025-05-19 起房东只能按法定理由拒绝（数量超过 4 只、围栏不合适、空间不够、无法人道饲养、损害很可能超过 bond、违反法律或 strata 规则、房东同住、租客拒绝合理条件），21 天不答复视为同意，不得为宠物加 bond；strata 一刀切禁宠的 by-law 无效。所以"可养宠"按法定流程判断，不按挂牌上一句 no pets。
- R-E4 2024-10-31 起涨租一年最多一次，禁止收背景调查费和合同准备费。总成本只算租金、bond、预付、bills、家具。

### F. 自己看房看到的（viewing 段）、建筑与公共设施

这一段的三条规则（R-F1 到 R-F3，编号不变）管的都是"材料里没有、要靠自己去看或问中介"的项。先说 viewing 段本身怎么用（不另编号，和 docs/00 第 6.1 节一致）：
- 租客按我们给的清单在看房时拍照、勾选：炉灶、空调内机位置、噪音、日照、新旧、水压、霉味。自己看到的是直接证据，记为"有支持（看房所见）"，分量和中介声明同级、低于法定表格和合同。
- 只勾看得见的。没看的房间仍是未知，不是"没问题"（同 R-B4）；白天去看只说明白天的噪音，夜间仍是未知；看到的日照只代表那个时段。
- 看房拍的照片走同一个看图模型（R-B 段的规则照样适用），但 source 标 renter，不和挂牌照片混；勾选项直接入表，不经模型。
- 代看房是可选服务，不是基础材料。代看的人用同一份清单，记录进 viewing 段，作者标 proxy，分量同租客自己看。
- 每条未知项的下一步只有三种：问中介（ask_agent）、看房时自己看（see_at_viewing）、签约时核（check_at_signing）。"看房时看"只给看房时一眼能确认的项（炉灶、内机、新旧、霉味、水压、噪音、日照）。

- R-F1 垃圾道、包裹房、管理员工时、电梯刷卡：只在 handbook、by-laws 或中介说明里。没有材料就是未知，不按楼龄楼高猜成"有"。排序可以用低置信先验，硬条件永远不算满足。下一步：问中介；包裹房、垃圾道这种一眼能看见的，看房时顺便看。
- R-F2 隔音没有任何法定材料记录。能用的线索都是低置信推断：楼龄、临路等级、机场噪音等高线、酒牌场所距离、by-laws 地板条款、AGM 噪音投诉。最终靠傍晚去看房（see_at_viewing）或问中介。
- R-F3 strata 记录租客无权直接查，AGM 和维修记录只能来自房东或中介（问）。但"固定租期内已排定的大修"属于必须披露，可以直接问（ask_agent）。

### G. 公开数据计算

- R-G1 通勤按用户的出发时刻算（早高峰），含步行和等待，注明时刻表日期。
- R-G2 租金比较注明季度和样本标记。
- R-G3 Census 只用住宅结构类字段（例如公寓占比）。不用年龄段、学生比例、国籍、语言；安静程度用噪音源数据，不用人口构成。

### H. 可选偏好规则包：风水

- R-H0 原则：默认关闭，用户说出在意风水才装进清单；不打总分，每条单独给状态和出处；界面上叫"文化偏好核对"，产品只核对用户在意的布局事实，不判断吉凶；凶宅是法定披露事实，走 R-E2，不在这个包里。
- R-H1 门牌、楼层数字（例如带 4）：读，来自挂牌地址。注意有的楼跳过 4 层或 14 层，楼层数字以挂牌标注为准，实际层数另标"推断"。
- R-H2 穿堂（入户门正对阳台门或大窗）：推断，来自户型图的门窗位置。只看户型，不考虑家具和屏风遮挡；门窗位置画不清就是未知。
- R-H3 开门见厕、开门见灶、厨厕门相对：推断，来自户型图。厕所门和炉灶位置户型图上标了才判；炉灶没标就是未知。
- R-H4 户型缺角（外轮廓不方正）：推断，来自户型图外轮廓。标注尺寸不全时只给低置信。
- R-H5 看不出来的一律未知，不编：床位和床头朝向（签约后用户自己摆）、横梁、天花高度、楼外尖角和路冲、门向配生辰。
- R-H6 真实户型图靠视觉模型读门窗位置时，置信度单独记录并显示；合成数据里直接用布局字段核对。

## 4. 清单项、来源、档位

"筛选阶段材料"是 listing、public、agent、viewing 四段里能用的；"签约时新增"是 signing 段，只做最后核对。首版维度的直接 / 间接 / 下一步总表在 docs/00 第 6.4 节。

| 清单项 | 筛选阶段材料 | 签约时新增（signing） | 档位 | 状态上限（筛选阶段） |
|---|---|---|---|---|
| 周租、bond、入住日、租期 | 挂牌 | 合同 | 读 | 有支持（营销）→ 签约前升为合同 |
| bills 谁付、包含项 | 挂牌文案 | 合同 | 读 | 推断 → 合同 |
| 几房几卫、共用卫生间 | 挂牌、户型 | 合同 | 读 | 有支持 |
| 卧室空调 | features（房产级）、照片内机、中介回复、看房自己看 | 条件报告 Y/N | 推 → 问 | 推断，除非中介回复或自己看到才是有支持 |
| 家具随租、具体哪些 | features、照片（不算）、中介回复点名 | inventory、合同 | 读（签约前） | 未知；中介点名后为有支持（声明） |
| 炉灶类型、烤箱、油烟机 | 照片、看房自己看 | 条件报告 Y/N | 推 → 问 | 燃气可读；电磁炉未知，看房时看 |
| 洗衣房位置、设备 | 户型、照片 | 条件报告 laundry 栏 | 推 | 推断 |
| 窗帘类型、插座数量 | 照片 | 条件报告（只记完好与否） | 推 → 问 | 推断 |
| 地板损坏、墙面、霉菌、虫害 | 看房自己看（勾选、照片） | 条件报告健康栏 Y/N | 读（有表时） | 未知，除非看房时自己看到了 |
| 车位、储物 | 挂牌、户型 | 合同、by-laws | 读 | 有支持 |
| 朝向 | 户型指北针 | 无 | 读 / 推 | 有指北针为有支持，否则未知 |
| 指定季节时段的直射日照 | 朝向、楼层、建筑高度数据 | 无 | 算 + 推 | 推断 |
| 通风 | 户型是否对穿、阳台门 | 无 | 推 | 推断 |
| 视野遮挡 | 阳台照片、楼层、建筑高度 | 无 | 推 | 推断 |
| 隔音、夜间噪音 | 楼龄、临路、噪音等高线、酒牌场所、傍晚看房 | AGM 投诉（问） | 推（低） → 问 | 推断（低） |
| 楼龄 | 挂牌、strata 资料 | 无 | 读 | 有支持 |
| 垃圾道、包裹房、管理员、电梯权限 | handbook | 无 | 读 / 问 | 未知，除非有 handbook |
| 通勤、超市、学校 | 地址 + 公开数据 | 无 | 算 | 有支持（计算） |
| 价格是否合理 | 周租 vs DCJ 中位数 | 无 | 算 | 有支持（计算，注明季度） |
| 竞争度 | 无 | 无 | 问 | 未知，口头答复记为声明 |
| NBN 类型、速度 | 地址公开查 | 条件报告通信栏 | 算 / 问 | 类型可读，速度未知 |

## 5. 和"思路"那份材料不同的几点

1. 条件报告的时点：它是签约前或签约时给的，不是筛选阶段材料，所以不能当筛选输入，只能当签约前核对。
2. CRM 竞争度：租客侧问不到正式数据，只能标"问"；产品卖给中介时才能读。
3. "没有 building sheet 就按楼龄楼高猜"：可以当低置信先验给排序用，但不能把硬条件算成满足，文档里要写明是猜的。
4. "floor plan 有指北针就高"：朝向可以高，日照不行，还差单元位置、楼层、邻楼遮挡，所以日照最多到"推断"。
5. Census 的年龄段、学生比例：不用。年龄是受保护属性，学生比例是年龄和国籍的代理变量；只用住宅结构类字段，安静度用噪音源。
6. 霉菌：条件报告有专门的 Y/N，所以"有表且填 No"是有支持，"没有表"才是未知。
7. "凶宅"这个梗可以正经做：5 年内严重暴力犯罪是法定必须披露的事实，放进"必问清单"；风水做成可选偏好规则包（规则 R-H 段），不打总分。
8. 虚拟软装：NSW 指引没有专门规定要标注，不能假设所有 staging 都带水印。

## 6. 对合成数据的直接要求

- 每套房的材料包按五段打 stage：listing（挂牌、照片、户型）、public（按锚点算的公开表）、agent（by-laws、handbook 可选、中介回复）、viewing（看房照片与勾选，只给模拟租客看过的那些套）、signing（合同草案、条件报告、inventory）。演示里"新材料到达"用 agent 段的中介回复或 viewing 段的看房照片；signing 段只用于签约前最后核对的演示，不参与排名。
- 条件报告按 Schedule 2 的真实房间和项目生成，用 Y/N 加评语的格式，含最低标准、健康问题、烟雾报警器、电气安全开关、通信、水效六个专栏。
- 每套房生成法定披露事实的真值（E2 的 11 加 3 项），中介回复里如实回答，偶尔含糊。
- 埋坑和规则一一对应：只写"有空调"（R-A1）；sun-drenched 对朝南（R-A2）；staging 或旧租客家具（R-A3、R-B1）；玻璃炉灶（R-B2）；没有指北针（R-C1）；没有条件报告对填 No（R-D3）；挂牌写 no pets（R-E3）；没有 handbook（R-F1）。
- 户型按结构化布局生成（房间多边形、门、窗、炉灶、厕所门的位置）再渲染成图，门牌和楼层写进地址。偏好包的坑：户型图没标炉灶、门画得不清，对应项必须输出未知。
- 真值和"材料够不够回答"两种标签同时打。材料答不了的，正确输出是未知，不奖励猜中。
