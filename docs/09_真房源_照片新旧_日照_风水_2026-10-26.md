## 0. 人话版

- **真房源**：从 Domain（绿）抓了 9 套悉尼东区两房出租房（Kensington / Kingsford / Randwick / Redfern，$780–950 一周），连照片、户型图、本区中位租金一起存在 data/real/。它们和 5 套合成房源并排参与查找；卡片和详情页用它们自己的照片，标 "Domain listing 17153470"，不再是示意图。红站（realestate.com.au）有 Kasada 防爬，没抓；正式产品该走 Domain 的开发者 API。
- **照片看新旧**：Nemotron VL 每张照片多报一项"装修看起来新 / 好 / 旧 / 破"和看见的迹象（台面材质、瓷砖、地毯、漆面）。规则把几张照片合成一格 **D1 Condition**：有破就破，厨房或卫生间旧就旧，有新没旧就新，其余算好。永远是"推断"（照片挑最好的时候拍，条件报告才是记录）；看着旧或破的那格不管租客问没问都讲，和盖章家具一样。
- **日照**：按经纬度 + 客厅主窗朝向算太阳几何（标准库，NOAA 公式）：冬至、夏至两天主窗能见太阳的时段和小时数。朝向从挂牌文字读（"easterly aspect"），文字没写就从户型图的指北针 + 阳台在哪面墙推（带置信度），都没有就是未知 → 该问中介。详情页多一段 **Sun and aspect**：等轴测的天空穹顶 + 小楼 + 两条太阳弧线，窗户看得见的那段加粗变暖，太阳沿冬至弧线动；下面一行行写清楚"冬至约 4.8 小时，06:35–11:20"和"没算邻楼遮挡，只是天空几何"。
- **风水 = 文化偏好核对**（docs/01 R-H 段）：默认关着，租客说出 "feng shui" 才进清单，四格各给状态和出处，不打总分、不判吉凶：K1 门牌楼层带不带 4（读地址）、K2 入户门是否直通阳台 / 大窗、K3 开门见厕 / 见灶 / 厨厕门相对、K4 外轮廓缺不缺角（K2–K4 由看图模型读户型图，置信度单独显示；没户型图就是未知，变成"请中介发户型图"）。
- **顺手补上的评委看得见的点**（docs/06 §7）：A1 租金那行多一条 "Domain：Kingsford 两房中位 $830，这套 $850（高 2%）"，台词也说；通勤对真房源是按直线距离估的，状态只到"推断"，证据写明"不是时刻表"。

## 3. 没做 / 要说清楚的

- 邻楼遮挡没有数据：日照是天空几何，不是实测；界面和台词都这么写（R-C3）。
- 真房源的通勤是直线距离估的，不是 TfNSW 时刻表；状态只到"推断"。
- 真房源不配任何合成文件：法定披露、水电、押金以外的文件都是未知 → 下一步标问中介；炉灶、噪音、新旧这类标看房时看。
- 风水包只核对布局事实；不做床位、横梁、生辰（R-H5）。
- 红站没抓（Kasada）；Domain 页面是浏览器里读 `__NEXT_DATA__`，正式产品走官方 API。
- 照片归中介公司所有，只在本机演示，不进仓库。
